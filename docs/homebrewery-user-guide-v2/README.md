 # Homebrewery User Guide - Technical Writing & Document Design Sample

This repository contains an exhaustive, production-grade **Comprehensive User Guide** for **The Homebrewery (NaturalCrit)**, an advanced browser-based editor that compiles Markdown and CSS into fifth-edition (5e) Dungeons & Dragons tabletop gaming layouts.

## 🎯 Project Overview
In modern software documentation ecosystems, Technical Writers must bridge the gap between abstract markup languages and visual layout constraints. This comprehensive manual (~1,000 lines of technical content) is designed to onboard content creators, game designers, and developers into formatting, structuring, and publishing professional game modules.

Rather than a surface-level tutorial, this project stands as a **Sénior-level portfolio sample** that details syntactic workflows, complex visual element rendering, framework limitations, and multi-platform compilation pipelines.

## 🚀 Key Learning Areas & Technical Concepts Documented
* **Core & Extended Markdown Integration:** Detailed behavior of thematic headings, blockquotes, definition lists (`::`), and text flow mechanics.
* **Complex Data Layouts & Multi-Column Mechanics:** Documentation on table alignments, wide layout blocks (`{{wide}}`), split tables, and complex 1st-20th multi-row level progression tables (Martial, Full Caster, and Third Caster specifications).
* **Advanced Visual Masking & Pipeline Pipelines:** Practical rules for image properties, absolute corner positioning, inline horizontal spacers, and complex CSS-based watercolor masks (`imageMaskEdge`, `imageMaskCenter`).
* **Compliance & Legal Operations:** A complete compliance matrix outlining licensing notices required for public software and content marketplace distribution (including OGL 1.0a, ORC, Creative Commons, and DriveThruRPG program requirements).
* **IDE & Document Lifecycle Tools:** Step-by-step functionality maps of internal toolchains, local browser history backup snapshot systems, linting formatting commands (`Clean your Code`), and Workspace state settings.

## 🛠️ Methodologies Demonstrated
* **Docs-as-Code Workflow:** Developed using professional Git branching structures and fully written in structural Markdown.
* **Conventional Commits Architecture:** Built systematically from the ground up utilizing strict semantic commit prefixes (`docs:`, `chore:`, `assets:`) to validate pipeline discipline.
* **Empathetic Information Architecture:** Structured with tight heading constraints, unambiguous error mitigation warnings, troubleshooting maps, and clear audience segmentation.
